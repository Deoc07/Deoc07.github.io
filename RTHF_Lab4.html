SQL injection attack, querying the database type and version on MySQL and Microsoft

Nombre del Laboratorio

SQL injection attack, querying the database type and version on MySQL and Microsoft.

Nivel

Practitioner (Nivel Intermedio).

Tipo de SQLi

UNION-based SQL Injection (Inyección SQL basada en uniones).

Objetivo del Laboratorio

Extraer la cadena que describe la versión de la base de datos para demostrar la capacidad de extraer datos sensibles mediante el parámetro de filtro de categorías.

Explicación Técnica

La vulnerabilidad ocurre porque la aplicación no sanitiza correctamente el input proporcionado en el parámetro category. Esto permite que un atacante cierre la consulta SQL original y añada una nueva consulta mediante el operador UNION.

Al ser una inyección basada en UNION, se deben cumplir dos condiciones:
1. Las consultas deben devolver el mismo número de columnas.
2. Los tipos de datos de las columnas deben ser compatibles entre sí.

Explicación del Payload

Accessories' UNION SELECT @@version, NULL#
': Cierra la cadena del filtro de categoría original.
UNION: Combina los resultados de la consulta original con los de nuestra consulta inyectada.
SELECT @@version, NULL: Nuestra consulta añadida. Selecciona la versión del servidor (en MySQL) y un valor nulo para completar las 2 columnas requeridas.
#: (O --) Carácter de comentario que anula el resto de la consulta SQL original para evitar errores de sintaxis.

Mitigación Recomendada

La defensa principal contra este ataque es el uso de Sentencias Preparadas (Prepared Statements) con consultas parametrizadas.
Ejemplo (Java/PHP/Node): En lugar de concatenar el string, se utiliza un marcador de posición (?). 

-- Incorrecto: "SELECT * FROM products WHERE category = '" + userInput + "'"
-- Correcto (Parametrizado): "SELECT * FROM products WHERE category = ?"

Otras medidas: Implementar una lista blanca (Whitelisting) de categorías permitidas y aplicar el principio de mínimo privilegio en el usuario de la base de datos.
