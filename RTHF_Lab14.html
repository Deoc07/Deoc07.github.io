Blind SQL injection with time delays

Nombre del laboratorio

Blind SQL injection with time delays (Inyección SQL ciega con retrasos de tiempo).

Tipo de SQLi

Inferential SQLi (Blind / Time-based).

Objetivo del laboratorio

Explotar la vulnerabilidad para pausar la ejecución de la consulta y provocar un retraso de 10 segundos en la respuesta de la aplicación.

Explicación técnica

A diferencia de otros tipos de SQLi, en este caso el servidor ha sido configurado para no mostrar diferencias visuales si la consulta falla o tiene éxito. La lógica de ataque se basa en:
Inyección en la Cookie: El punto de entrada es la tracking cookie.
Uso de Funciones de Tiempo: Se insertan comandos como pg_sleep(10), WAITFOR DELAY '0:0:10' o SLEEP(10).
Confirmación: Si la página tarda exactamente 10 segundos adicionales en cargar, se confirma la ejecución del código inyectado.
Extracción Teórica: Esta técnica permite condicionar retrasos para inferir datos carácter por carácter.

Procedimiento paso a paso

Acceso inicial

Acceder a la instancia del laboratorio con BurpSuite, buscar la petición con la cookie TrackingId y enviarla al Repeater.

Imagen 1

Inyección de retraso

Modificar el valor de la cookie a TrackingId=x'||pg_sleep(10)-- y enviar la solicitud. La respuesta tardará 10 segundos en cargarse.

Imagen 2

Confirmación

Una vez cargada la solicitud, el laboratorio aparecerá como completado.

Imagen 3

Mitigación recomendada

Uso estricto de ORMs o Sentencias Preparadas: Evitar que funciones como pg_sleep() sean interpretadas.
Limitación de Privilegios: El usuario de la base de datos no debe tener permisos para ejecutar funciones de sistema.
Web Application Firewall (WAF): Detectar patrones sospechosos en cookies y bloquearlos.
Timeouts en Consultas: Configurar un tiempo máximo de espera para cortar consultas que excedan lo normal.
