SQL injection vulnerability in WHERE clause allowing retrieval of hidden data

Nombre del laboratorio

SQL injection vulnerability in WHERE clause allowing retrieval of hidden data.

Nivel

Apprentice.

Tipo de SQLi

In-band (cláusula WHERE).

Objetivo del laboratorio

Modificar la consulta para mostrar productos que no han sido lanzados (donde released = 0).

Explicación técnica

La vulnerabilidad ocurre porque el input del usuario en el parámetro category se concatena directamente en una consulta WHERE. Esto permite romper la lógica booleana original (released = 1) e insertar una condición que siempre sea verdadera (1=1), forzando al motor de base de datos a devolver todos los registros de la tabla.

Procedimiento paso a paso

Fase de Reconocimiento

Acceder a la página principal y navegar por las categorías de productos (en mi caso "Accessories"). Observar cómo la URL cambia añadiendo el parámetro ?category=.

Imagen 1

Intercepción Profesional

Activar Intercept en Burp Suite y recargar la página de la categoría seleccionada. Capturar la petición GET /filter?category=Accessories HTTP/2.

Imagen 2

Análisis en Repeater

Enviar la petición al Repeater para realizar pruebas aisladas. Realizar una petición limpia para establecer una línea base de cuántos productos se muestran normalmente.

Imagen 3

Inyección y Modificación

En la pestaña del Repeater, modificar el valor del parámetro a: Accessories' OR 1=1--.

Imagen 4

Análisis de Respuesta

Hacer clic en Send. En el panel de Response verificar que el código de estado sea 200 OK.

Explicación del payload

' OR 1=1--
El ' termina prematuramente la cadena de texto de la categoría.
OR 1=1 altera la lógica de la consulta (WHERE category = 'Accessories' OR 1=1), haciendo que toda la fila sea seleccionada independientemente de si la categoría coincide o si está lanzada.
-- funciona como comentario para anular el resto de la sintaxis original.

Mitigación recomendada

Implementar Prepared Statements con parámetros tipados para evitar la interpretación de metacaracteres SQL.
