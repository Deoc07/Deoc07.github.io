Blind SQL injection with conditional errors

Nombre del laboratorio

Blind SQL injection with conditional errors.

Nivel

Apprentice.

Tipo de SQLi

Blind SQL injection con errores condicionales.

Objetivo del laboratorio

Obtener la contraseña del usuario administrador y usarla para iniciar sesión.

Explicación técnica

Este tipo de ataque de SQL Injection no muestra los resultados directamente en la pantalla. En su lugar, se infiere la información observando si la consulta inyectada provoca un error en la base de datos o si devuelve un código de estado 200. Al generar errores controlados basándose en condiciones verdaderas o falsas, se puede determinar la existencia de tablas, usuarios o caracteres específicos de la contraseña.

Procedimiento paso a paso

Acceso inicial

Ingresar al laboratorio y observar que las categorías no son vulnerables.

Imagen 1

Identificación de campo vulnerable

Identificar que la inyección se realiza en el campo TrackingId de la cookie. Modificar el TrackingId y verificar que una comilla simple (') genera un error, confirmando la vulnerabilidad.

Imagen 2

Preparación en Burp Suite

Interceptar la petición y enviarla al Repeater.

Imagen 3

Determinación del tipo de base de datos

Inyectar un payload de prueba como ' || (SELECT '') || ' y observar que genera un error 500.
Añadir FROM DUAL al payload para Oracle: ' || (SELECT '' FROM DUAL) || ' y verificar que devuelve un código 200. Esto confirma que es una base de datos Oracle.

Imagen 4

Confirmación de tabla users

Payload: ' || (SELECT '' FROM users WHERE ROWNUM = 1) || '. URL-codificar y enviar. Un código 200 confirma la existencia de la tabla users.

Imagen 5

Confirmación de usuario administrator

Payload: ' || (SELECT CASE WHEN (1=1) THEN 1/0 ELSE '' END FROM users WHERE username='administrator') || '. Un error 500 indica que el usuario administrator existe.

Imagen 6

Determinación de longitud de contraseña

Payload: ' || (SELECT CASE WHEN (LENGTH(password) > X) THEN 1/0 ELSE '' END FROM users WHERE username='administrator') || '. Ajustar X hasta encontrar el umbral correcto. Se confirma que la longitud es 20 caracteres.

Imagen 7 Imagen 8

Extracción de caracteres

Payload: ' || (SELECT CASE WHEN (SUBSTR(password, {posicion}, 1) = '{caracter}') THEN 1/0 ELSE '' END FROM users WHERE username='administrator') || '. Se prueba carácter por carácter usando Intruder o un script Python.

Imagen 9 Imagen 10

Automatización con script Python

El script prueba cada posición de la contraseña y cada carácter posible. Si la respuesta es 500, el carácter es correcto; si es 200, no lo es.

Imagen 11

Inicio de sesión

Una vez obtenida la contraseña completa, ir a "My account". Ingresar administrator y la contraseña extraída.

Imagen 12 Imagen 13

Respuesta vulnerable

El código de estado HTTP de la respuesta del servidor (500 o 200).

Confirmación

Inicio de sesión exitoso como administrator.

Explicación del payload

El payload utiliza la función SUBSTR de Oracle para extraer un carácter específico de la contraseña en una posición determinada. Luego, compara este carácter con uno de prueba. Si la comparación es verdadera, se provoca un error de división por cero (código 500). Si es falsa, devuelve una cadena vacía (código 200). Este comportamiento condicional permite inferir la contraseña carácter por carácter.

Mitigación recomendada

Validación estricta de entradas: Implementar validación de entradas para rechazar caracteres inesperados.
Mensajes de error genéricos: Mostrar errores genéricos en lugar de detalles técnicos.
Principio de Mínimo Privilegio: Configurar el usuario de la base de datos con permisos mínimos.
Web Application Firewalls (WAFs): Implementar WAFs para detectar patrones de inyección SQL ciega.
