SQL injection with filter bypass via XML encoding

Nombre del Laboratorio

SQL injection with stock check feature.

Nivel

Practitioner (Nivel Intermedio).

Tipo de SQLi

SQL Injection con evasión de filtros (WAF bypass) mediante codificación XML.

Introducción y Contexto Técnico

En este escenario, la aplicación implementa la funcionalidad "Check stock". Los datos se envían en formato XML dentro de una petición POST. El WAF bloquea patrones comunes de SQLi, pero se evade mediante codificación hexadecimal en el XML.

Objetivo del Laboratorio

Vulnerar la consulta SQL que procesa el stock de productos para extraer las credenciales del usuario administrator, evadiendo el WAF con una inyección UNION codificada en XML.

Explicación Técnica de la Vulnerabilidad

La vulnerabilidad se encuentra en la etiqueta <storeId>. El servidor decodifica entidades XML antes de ejecutar la consulta SQL. Al enviar palabras clave codificadas (ej. &#x53; en lugar de S), el WAF no detecta el ataque, pero la base de datos ejecuta el comando completo tras la decodificación.

Procedimiento Paso a Paso

Captura y Análisis

Navegar a un producto y presionar "Check stock". Interceptar la petición en el Proxy y enviarla al Repeater.

Imagen 1 Imagen 2

Prueba de Inyección Inicial

Modificar <storeId> con 1+1. El servidor devuelve el stock de la tienda ID 2, confirmando que el campo es procesado numéricamente.

Imagen 3 Imagen 4

Detección del Filtro (WAF)

Intentar 1 UNION SELECT NULL provoca error de seguridad, confirmando la presencia del WAF.

Codificación para Bypass

Reemplazar las palabras clave por entidades hexadecimales XML. Ejemplo: &#x55;NION &#x53;ELECT.

Imagen 5

Construcción del Exploit Final

Payload: 1 &#x55;NION &#x53;ELECT username || '~' || password FROM users--
Se concatena usuario y contraseña en una sola columna.

Ejecución y Extracción

Enviar la petición codificada. El servidor responde con 200 OK y muestra administrator~contraseña.

Imagen 6 Imagen 7

Análisis de Resultados

La respuesta demuestra que el WAF fue evadido mediante codificación XML. La base de datos ejecutó la consulta maliciosa y devolvió las credenciales del administrador, permitiendo iniciar sesión y resolver el laboratorio.

Mitigación Recomendada

Uso de Parsers XML Seguros: Configurar el parser para no resolver entidades externas.
Consultas Parametrizadas: Implementar sentencias preparadas para evitar ejecución de comandos SQL.
Mejora del WAF: Configurar el firewall para decodificar datos antes de aplicar reglas de filtrado.
