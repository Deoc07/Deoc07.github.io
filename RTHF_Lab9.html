Ataque UNION de inyección SQL, recuperando datos de otras tablas

Nombre del laboratorio

Ataque UNION de inyección SQL, recuperando datos de otras tablas.

Nivel

Apprentice.

Tipo de SQLi

In-band (Union-based).

Objetivo del laboratorio

Exfiltrar los nombres de usuario y contraseñas de la tabla users y utilizarlos para iniciar sesión como administrador.

Explicación técnica

Este ataque permite acceder a tablas que no tienen relación directa con la funcionalidad original (catálogo de productos). El atacante "roba" el flujo de datos de la página para redirigir información de la tabla de credenciales hacia la interfaz pública.

Procedimiento paso a paso

Acceder a una categoría

(ej. "Tech gifts").

Imagen 1

Intercepción

Utilizar Burp Suite para interceptar y modificar la solicitud que establece el filtro de categoría de producto.

Imagen 2

Confirmación de columnas

Determinar que hay 2 columnas disponibles y que ambas aceptan texto.

Imagen 3

Inyección del payload

Inyectar el payload para extraer datos: ' UNION SELECT username, password FROM users--.

Imagen 4

Localización de credenciales

Localizar en la respuesta del navegador la lista de usuarios y contraseñas.
Identificar la credencial del usuario “administrador”.

Imagen 5

Acceso

Ir a la sección "My account" y loguearse con la contraseña obtenida.

Imagen 6

Respuesta vulnerable

Lista de credenciales en el HTML.

Confirmación

Inicio de sesión exitoso como administrador y banner de "Lab Solved".

Imagen 7

Explicación del payload

La parte SELECT username, password FROM users solicita a la base de datos que busque en la tabla users (una tabla común en estos sistemas) y traiga los valores de las columnas de identificación. La unión hace que estos datos aparezcan donde normalmente estarían los nombres de los productos.

Mitigación recomendada

Aplicar el Principio de Mínimo Privilegio. El usuario de la base de datos que utiliza la aplicación web no debería tener permisos de lectura sobre la tabla users o tablas administrativas del sistema.
